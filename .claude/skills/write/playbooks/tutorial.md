# Playbook — Tutorial / how-to

For teaching a task the viewer will actually do: software steps, recipes, DIY,
setup guides, tips. The viewer should **be able to do it after watching**.

## Defaults

| | |
|-|-|
| Length | 30–60 s (single trick), 2–5 min (full walkthrough) — default 45 s |
| Hook window | first 3 s (≤ 8 spoken words) |
| Pace | 2.3 wps — steady; leave time to see each step |
| Tone | clear, encouraging, practical; a patient expert |
| Point of view | imperative "you": "Open settings. Tap privacy." |

## Hook formulas

1. **Result first** — show the finished outcome, then "here's how".
   "This is a pro headshot. I took it on a ninety-rupee phone stand."
2. **Time / effort promise** — specific and true.
   "Fix a slow laptop in three steps. Two minutes."
3. **Mistake call-out** — the common wrong way.
   "You're charging your phone wrong. Here's the right way."
4. **Hidden feature** — something already in the viewer's hands.
   "Your phone has a document scanner. It's hidden here."
5. **Problem → instant fix** — name a pain, promise the fix.
   "Wi-Fi keeps dropping? Change this one setting."

## Structure

| Beat | Share of time | Job |
|------|---------------|-----|
| Hook | ~8% | Show/promise the result |
| What you need | ~7% | Tools, versions, prerequisites (skip if none) |
| Steps | ~65% | One beat per step, numbered, in order |
| Result + check | ~10% | What success looks like, how to verify |
| Tip / common mistake | ~5% | One pro tip or pitfall |
| CTA | ~5% | Save this / follow for more |

## Writing rules

- **One action per sentence**, in the order the viewer does it.
- **Name UI elements exactly** as they appear on screen (button labels in
  ON-SCREEN, quoted). Note the app/OS version if steps vary.
- **Number steps when the viewer needs to track or revisit them**, especially in
  longer instructions. Otherwise narrate the actions directly and keep numbers
  on screen. Avoid a separate "Now, step two" sentence before the actual action.
- **Say where, then what:** "In the top right, tap the three dots."
- **Include the check:** how the viewer knows the step worked.
- **Safety:** for anything physical, electrical, chemical or financial, include the
  relevant caution in VO, not just on screen.
- ON-SCREEN text: step numbers, button names, values to type, shortcuts.

## CTA patterns

- "Save this so you have it when you need it."
- "Follow for one useful trick a day."
- "Comment which step tripped you up."

## Avoid

- Skipping "obvious" steps
- Explaining theory mid-steps — put it before or after
- Steps that differ by device without saying so
- Unverified steps — if unsure of exact menus/labels, mark `[UNVERIFIED]` and ask
